# 巡查台账汇总分析系统

把各厂区多种格式的巡查台账 Excel 汇总成一张统一的数据库表，然后做关键词筛选与统计出图。

```
Excel（多文件 / 整个文件夹 / ZIP） ──▶ 序号 · 日期 · 巡查发现 ──▶ 筛选 / 统计 / 导出
```

---

## 功能一览

| # | 功能 | 说明 |
|---|---|---|
| ① | **数据汇总** | 上传文件、ZIP（整个文件夹）或填写文件夹路径；自动识别 4 类台账的日期列与「巡查发现」列，整理成 `序号 / 日期 / 巡查发现` 数据库，一键导出 Excel |
| ② | **关键词筛选** | 支持 `A&B`（同时含）、`A|B`（含其一）及多级组合，显示命中总数，一键导出 Excel |
| ③ | **关键词统计** | 关键词清单可增 / 删 / 勾选，生成条形图或饼图，可保存 PNG / HTML，并导出统计表 |

---

## 快速开始

```bash
pip install -r requirements.txt
streamlit run inspection_app.py
```

浏览器打开终端提示的地址（默认 <http://localhost:8501>）。

在「① 数据汇总」里把文件夹名填进「文件夹路径」，例如：

```
各厂区所有巡查项---2026年1月1日至2026年7月31日
```

点 **🚀 开始汇总整理** 即可。

## 功能① 数据汇总

### 三种上传方式（可混用）

| 方式 | 适用场景 | 说明 |
|---|---|---|
| **多选文件** | 手上就是几个 Excel | 在文件选择框里可一次框选某个文件夹内的全部 Excel |
| **上传 ZIP** | 想「上传整个文件夹」/ 文件较多 | 浏览器不支持直接选文件夹；把文件夹压缩成 zip 上传，程序会递归取出里面所有 Excel（自动跳过 `__MACOSX`、`~$` 临时文件） |
| **文件夹路径** | 本地运行 / 数据已在仓库里 | 每行填一个路径；也可从下拉框里选仓库中已有的数据文件夹 |

同名文件只保留一份，避免重复计数。

> **文件多时建议先打包成 ZIP。** xlsx 本身已是压缩格式，17 个文件打包后从 9.6 MB 只降到 9.2 MB，
> 但上传请求数会从 17 次变成 1 次 —— 在跨境或高延迟网络下差别很明显。

### 台账类型自动识别

「巡查发现」在不同台账里叫法不同，程序按 文件名 → sheet 名 → 列名 三级判定：

| 台账类型 | 文件名关键字 | 日期列 | 「巡查发现」实际列名 |
|---|---|---|---|
| 日常隐患排查 | `日常隐患排查` | 巡查日期 | **巡查发现** |
| 高管驻场 | `高管驻场` / `高管驻厂` | 日期 | **巡查结果** |
| 值班巡查 | `值班巡查` | 值班日期 | **发现项** |
| 全体人员巡查 | `全体人员巡查` / `生产人员巡查` | 时间 | **问题描述** |

其它细节：

- **表头行自动定位** —— 这些台账第 1 行往往是合并的大标题，真正的列名在第 2 行；程序会依次尝试第 2 / 1 / 3 行，取能找到「巡查发现」列的那一个
- **日期兼容** —— `2026/3/20`、`2026/7/13 0:00:00`、`2026-03-20`、datetime 对象、Excel 序列号都能解析；`创建时间 / 修改时间 / 复核日期` 等不会被误当成巡查日期
- **遇到没见过的台账** —— 按候选列名匹配，都不中时选平均文本最长的那一列，并在「各文件识别详情」里如实显示所选列，便于核对
- 单个文件解析失败不会中断整批，错误原因会列在识别详情表里

### 输出

导出的 Excel 默认就是需求要求的三列：

| 序号 | 日期 | 巡查发现 |
|---|---|---|
| 1 | 2026-01-01 | 11号楼2层监控有较多点位无画面 |
| 2 | 2026-01-01 | 2-101实验室北侧清洗器未使用时未断电 |

- `序号` 按最终顺序从 1 连续编号（默认按日期升序）
- 勾选「附带来源文件 / 台账类型」可额外输出 2 列溯源信息
- 可选对完全重复的 `(日期 + 巡查发现)` 去重

## 功能② 关键词筛选

| 输入 | 含义 |
|---|---|
| `物料` | 「巡查发现」里包含 *物料* |
| `物料&泄漏` | **同时**包含 *物料* 和 *泄漏* |
| `静电\|接地` | 包含 *静电* **或** *接地* |
| `A&B&C` | 同时包含三者 |
| `A\|B\|C` | 三者之一 |
| `A&B\|C` | `&` 优先于 `\|`，等价于 `(A&B) \| C` |

- 全角 `＆` `｜` 同样识别
- 界面会把条件翻译成中文（例如「满足以下任一条件: 同时包含「物料」且「痕迹」；或 同时包含「气味」且「扩散」」），方便确认没写错
- 显示命中条目总数与占比，导出的 Excel 附带一张「筛选条件」说明表

---

## 功能③ 关键词统计

- 输入框 + **➕ 添加** 维护关键词清单（同样支持 `&` 和 `|`），重复添加会被拦截
- 每行一个 **勾选框**（控制是否进图表）和一个 **🗑 删除按钮**；另有 **全选 / 全不选 / 清空全部**
- 每个关键词旁边实时显示命中条目数
- 图表类型：竖向条形图 / 横向条形图 / 饼图 / 环形图；可排序、可显示数值
- **保存图表**：PNG（需要 kaleido）、HTML（自包含网页，任何环境都可用）、统计数据 Excel

## 项目结构

```
.
├── inspection_app.py              # Streamlit 界面（三个功能页）
├── inspection_pipeline/
│   ├── schema.py                  # 3 字段定义 + 各类台账列名映射
│   ├── reader.py                  # 单个 Excel 智能解析（表头 / 日期 / 巡查发现）
│   ├── collector.py               # 收集来源（多文件 / ZIP / 文件夹）
│   ├── database.py                # SQLite 存储层
│   ├── query.py                   # 关键词表达式（& / |）解析与筛选
│   ├── charts.py                  # Plotly 图表 + PNG/HTML 导出
│   └── exporter.py                # Excel 导出
├── requirements.txt
├── .streamlit/config.toml
└── 各厂区所有巡查项---2026年1月1日至2026年7月31日/   # 示例数据
```

### 为什么用 SQLite 存数据库

- 标准库自带，不用装数据库服务，一个 `data/inspection.db` 文件跟着项目走
- 支持 SQL 查询，几万条数据检索仍是毫秒级
- 关掉页面再打开会**自动载入上次整理的数据**，不必重新上传

表结构：

```sql
inspections(序号 INTEGER PRIMARY KEY, 日期 TEXT, 巡查发现 TEXT,
            来源文件 TEXT, 台账类型 TEXT)
```

## 性能说明：为什么「上传」会觉得慢

整个过程分两段，慢的往往不是同一段：

| 阶段 | 决定因素 | 能否优化 |
|---|---|---|
| ① 浏览器 → 服务器传输 | **你的上传带宽 + 网络延迟**（9.6 MB） | 打包成 ZIP 可把 17 次请求降为 1 次 |
| ② 服务器解析 Excel | 服务器 CPU | 已优化，见下 |

解析阶段做过的优化（同一批 17 个文件、同一台机器实测）：

| 版本 | 解析耗时 |
|---|---|
| 初版（openpyxl + 探测读一遍再全量读一遍） | 5.9 s |
| 改用 [calamine](https://pypi.org/project/python-calamine/)（Rust 实现）+ 每张表只读一次 | **1.5 s** |

- `python-calamine` 装不上时会**自动回退 openpyxl**，功能不受影响，只是慢一些
- 界面上「完成！…」提示里会显示本次实际解析耗时，方便判断是网络慢还是解析慢
- 免费层的服务器 CPU 比本地弱不少，同样的数据在云端会比上面的数字慢几倍属正常

### 界面交互速度

Streamlit 的机制是**每次交互都重跑整个脚本**，所以任何写在脚本里的重活都会被反复执行。
实测（68,499 条数据）定位到两个大头，都已按内容签名缓存：

| 每次 rerun 原本都在做的事 | 单次耗时 |
|---|---|
| `st.download_button(data=...)` 重新生成整份汇总 Excel | 1774 ms |
| kaleido 渲染图表 PNG | 1241 ms |

另外关键词匹配也做了优化：改用 numpy + Python 原生 `in`（比 `pandas.str.contains`
和 `pyarrow.match_substring` 都快约 3 倍），`&` 查询逐步收窄候选集、`|` 查询跳过已命中行，
并把预处理后的搜索数组和每个关键词的命中数缓存起来复用。

优化前后（本地实测）：

| 操作 | 优化前 | 优化后 |
|---|---|---|
| 筛选 | 2.0 – 2.3 s | **0.4 – 0.6 s** |
| 添加一个关键词 | 2.0 – 4.0 s | **0.3 – 0.5 s** |
| 切换一个勾选框 | 3.3 s | **0.4 s** |
| 生成图表 | 3.7 s | **1.0 s** |

> 高清 PNG 默认不预先生成（勾选后才做）。图表右上角的 📷 本来就能即时存图，
> 不需要服务器参与。

## 部署到公网

### Streamlit Community Cloud（免费）

1. 打开 <https://share.streamlit.io>，用 GitHub 登录
2. **New app**，填写：
   - Repository：本仓库
   - Branch：本分支
   - **Main file path：`inspection_app.py`**
3. Deploy

### Render（免费，休眠后冷启动约 30–60 秒）

- Build Command：`pip install -r requirements.txt`
- Start Command：
  ```
  streamlit run inspection_app.py --server.port=$PORT --server.address=0.0.0.0 --server.headless=true
  ```

> 云端注意：容器文件系统是临时的，`data/inspection.db` 会在应用重启后丢失，重新上传整理即可。若 kaleido 在云端不可用，PNG 按钮会自动禁用并提示改用 HTML 或图表自带的相机按钮。

# 巡查台账汇总分析系统

把各厂区多种格式的巡查台账 Excel 汇总成一张统一的数据库表，然后做关键词筛选与统计出图。

```
Excel（多文件 / 整个文件夹 / ZIP） ──▶ 序号 · 日期 · 巡查发现 ──▶ 筛选 / 统计 / 导出
```

---

## 功能一览

| # | 功能 | 说明 |
|---|---|---|
| ① | **数据汇总** | 上传文件、ZIP（整个文件夹）或填写文件夹路径；自动识别 4 类台账的日期列、厂区与「巡查发现」列，整理成 `序号 / 日期 / 厂区 / 巡查发现` 数据库，一键导出 Excel |
| ② | **关键词筛选** | 支持 `A&B`（同时含）、`A|B`（含其一）；可按**厂区**限定范围；支持**多级筛选**（在上一级结果里继续筛）；可把结果**加入统计清单**；一键导出 Excel |
| ③ | **关键词统计** | 关键词清单可增 / 删 / 勾选，可按**厂区**限定范围，生成条形图或饼图，可保存 PNG / HTML，并导出统计表 |

## 快速开始

### Windows：双击 `启动巡查分析.bat`

把项目文件夹放到本机任意位置，**双击 `启动巡查分析.bat`** 即可。脚本一共 8 行，做的就是
你手敲的那几步：切到脚本所在目录 → `pip install -r requirements.txt` →
`streamlit run inspection_app.py` → 服务就绪后自动打开 <http://localhost:8501>。

关掉那个黑色命令行窗口，或在里面按 `Ctrl+C`，就停止程序。

两个说明：

- 脚本文件是 **GBK 编码**的。中文 Windows 的控制台默认用 936 代码页，
  存成 UTF-8 会显示乱码，所以不要用编辑器另存为 UTF-8。
- 用 `--server.headless=true` 启动，浏览器由脚本自己打开。
  这样既能跳过 Streamlit 首次运行时那个要你填邮箱的提示（否则窗口会卡住不动），
  也保证只打开一个标签页；打开时机是靠轮询 `/_stcore/health`，不会打开太早。

### 手动运行（macOS / Linux，或想自己控制）

```bash
pip install -r requirements.txt
streamlit run inspection_app.py
```

浏览器打开终端提示的地址（默认 <http://localhost:8501>）。

在「① 数据汇总」里把文件夹名填进「文件夹路径」，例如：

```
各厂区所有巡查项---2026年1月1日至2026年7月31日
```

点 **🚀 开始汇总整理** 即可。

## 功能① 数据汇总

### 三种上传方式（可混用）

| 方式 | 适用场景 | 说明 |
|---|---|---|
| **多选文件** | 手上就是几个 Excel | 在文件选择框里可一次框选某个文件夹内的全部 Excel |
| **上传 ZIP** | 想「上传整个文件夹」/ 文件较多 | 浏览器不支持直接选文件夹；把文件夹压缩成 zip 上传，程序会递归取出里面所有 Excel（自动跳过 `__MACOSX`、`~$` 临时文件） |
| **文件夹路径** | 本地运行 / 数据已在仓库里 | 每行填一个路径；也可从下拉框里选仓库中已有的数据文件夹 |

同名文件只保留一份，避免重复计数。

> **文件多时建议先打包成 ZIP。** xlsx 本身已是压缩格式，17 个文件打包后从 9.6 MB 只降到 9.2 MB，
> 但上传请求数会从 17 次变成 1 次 —— 在跨境或高延迟网络下差别很明显。

### 台账类型自动识别

「巡查发现」在不同台账里叫法不同，程序按 文件名 → sheet 名 → 列名 三级判定：

| 台账类型 | 文件名关键字 | 日期列 | 「巡查发现」实际列名 |
|---|---|---|---|
| 日常隐患排查 | `日常隐患排查` | 巡查日期 | **巡查发现** |
| 高管驻场 | `高管驻场` / `高管驻厂` | 日期 | **巡查结果** |
| 值班巡查 | `值班巡查` | 值班日期 | **发现项** |
| 全体人员巡查 | `全体人员巡查` / `生产人员巡查` | 时间 | **问题描述** |

### 厂区自动归属

认可的厂区代号：`TJ1 TJ2 TJ3 TJ4 TJ6 FX1 FX2 DH1 DH2 DH3 SH1 SH2 SH3 SH4`

判定顺序（**一条数据只归一个厂区**）：

1. **文件名里出现厂区代号** → 整个文件的所有行都算该厂区
   （例如 `…（DH1值班巡查）.xlsx` 全部算 DH1）
2. 文件名没有 → 看内容里的厂区列，优先级 **整改厂区 → 厂区 → 组织厂区**

归一化规则：

- `TJ4-CMMD`、`TJ4-CSBT`、`TJ4CMMD` 一律并入 **TJ4**
- 代号后面紧跟数字的**不会**误配：`TJ10_CSBT` 不会被当成 TJ1
- 不在上面 14 个代号里的（数据里实际存在 `TJ5_CMMD`、`TJ7_CSBT`、`TJ9_CSBT`、`TJ10_CSBT` 等）
  记为 **`未识别`**，不会被丢弃，筛选和统计里也能选到

### 其它细节

- **表头行自动定位** —— 这些台账第 1 行往往是合并的大标题，真正的列名在第 2 行；程序会依次尝试第 2 / 1 / 3 行，取能找到「巡查发现」列的那一个
- **日期兼容** —— `2026/3/20`、`2026/7/13 0:00:00`、`2026-03-20`、datetime 对象、Excel 序列号都能解析；`创建时间 / 修改时间 / 复核日期` 等不会被误当成巡查日期
- **遇到没见过的台账** —— 按候选列名匹配，都不中时选平均文本最长的那一列，并在「各文件识别详情」里如实显示所选列，便于核对
- 单个文件解析失败不会中断整批，错误原因会列在识别详情表里

### 输出

导出的 Excel 默认是这四列：

| 序号 | 日期 | 厂区 | 巡查发现 |
|---|---|---|---|
| 1 | 2026-01-01 | DH1 | 11号楼2层监控有较多点位无画面 |
| 2 | 2026-01-01 | TJ3 | 2-101实验室北侧清洗器未使用时未断电 |

- `序号` 按最终顺序从 1 连续编号（默认按日期升序）
- 勾选「附带来源文件 / 台账类型」可额外输出 2 列溯源信息
- 可选对完全重复的 `(日期 + 厂区 + 巡查发现)` 去重
  （同一句描述出现在两个厂区算两条，所以厂区也纳入去重键）

## 功能② 关键词筛选

| 输入 | 含义 |
|---|---|
| `物料` | 「巡查发现」里包含 *物料* |
| `物料&泄漏` | **同时**包含 *物料* 和 *泄漏* |
| `静电\|接地` | 包含 *静电* **或** *接地* |
| `A&B&C` | 同时包含三者 |
| `A\|B\|C` | 三者之一 |
| `A&B\|C` | `&` 优先于 `\|`，等价于 `(A&B) \| C` |

- 全角 `＆` `｜` 同样识别
- 界面会把条件翻译成中文（例如「满足以下任一条件: 同时包含「物料」且「痕迹」；或 同时包含「气味」且「扩散」」），方便确认没写错
- 显示命中条目总数与占比，导出的 Excel 附带一张「筛选条件」说明表

### 厂区范围

顶部有「厂区」多选框，**不选就是全部厂区**；选了之后只在这些厂区里筛。

**换厂区后结果和默认名称都会自动跟着变**，不需要再点一次筛选：

| 厂区选择 | 命中（阀门） | 加入统计清单的默认名称 |
|---|---|---|
| 不选（全部厂区） | 3,571 | `阀门` |
| TJ4 | 412 | `【TJ4】阀门` |
| TJ3 + TJ4 | 654 | `【TJ3+TJ4】阀门` |

### 多级筛选

第 2 级在第 1 级的结果里继续筛，第 3 级在第 2 级的结果里继续筛……层数不限，
只填第 1 级就是普通单层筛选。点「➕ 添加下一级」加一层，每层右边的 🗑 可删掉该层。

例如 第 1 级 `阀门` → 第 2 级 `渗漏|管路`：

| 层级 | 命中 |
|---|---|
| 阀门 | 3,571 |
| → 渗漏\|管路 | 1,206 |
| → 再限定厂区 DH1 | 523 |

多级条件会被换算成一个等价的单表达式（上例是 `阀门&渗漏|阀门&管路`），
所以能直接存进统计清单，也会写进导出 Excel 的「筛选条件」表。

### 把结果加入统计清单

筛出结果后，下方可以一键 **➕ 加入统计清单**（即功能③ 的清单）。
名称默认是「厂区 + 层级串」，例如 `【TJ4】阀门 → 渗漏|管路`，也可以自己填。
推送时会把**当时选的厂区一起带过去**，所以换个厂区再推一条，
就能在同一张图里做跨厂区对比。

## 功能③ 关键词统计

**每个关键词自带厂区**，所以同一张图里可以做跨厂区对比（如 TJ4 的阀门 vs TJ3 的阀门）。

- 顶部「厂区」多选框只决定**新加入**的关键词用什么范围；清单里已有的条目各记着自己的厂区，不会被改动
- 关键词输入框前面会显示当前范围，例如 `【TJ3+TJ4】`，一眼看出这条会记到哪个厂区
- 勾上「**为选中的每个厂区分别加一条**」后，选中 TJ3 与 TJ4 再输入 `阀门`，一次就得到
  `【TJ3】阀门` 和 `【TJ4】阀门` 两条 —— 跨厂区对比最快的做法
- 清单每行显示 名称 / 厂区 / 表达式 / 命中条目数；重复添加会被拦截
- 每行一个 **勾选框**（控制是否进图表）和一个 **🗑 删除按钮**；另有 **全选 / 全不选 / 清空全部**
- 「占该厂区比例」= 命中数 ÷ **该条目所属厂区**的总条目数，所以不同厂区之间的比例也能直接比

例如：

| 名称 | 厂区 | 条目数 | 占该厂区比例 |
|---|---|---|---|
| 【TJ4】阀门 | TJ4 | 412 | 3.06% |
| 【TJ3】阀门 | TJ3 | 242 | 2.52% |
| 阀门 | 全部厂区 | 3,571 | 5.21% |
- 图表类型：竖向条形图 / 横向条形图 / 饼图 / 环形图；可排序、可显示数值
- **保存图表**：PNG（需要 kaleido）、HTML（自包含网页，任何环境都可用）、统计数据 Excel

## 项目结构

```
.
├── 启动巡查分析.bat                # Windows 一键启动（双击即可）
├── inspection_app.py              # Streamlit 界面（三个功能页）
├── inspection_pipeline/
│   ├── schema.py                  # 3 字段定义 + 各类台账列名映射
│   ├── reader.py                  # 单个 Excel 智能解析（表头 / 日期 / 巡查发现）
│   ├── collector.py               # 收集来源（多文件 / ZIP / 文件夹）
│   ├── database.py                # SQLite 存储层
│   ├── query.py                   # 关键词表达式（& / |）解析与筛选
│   ├── charts.py                  # Plotly 图表 + PNG/HTML 导出
│   └── exporter.py                # Excel 导出
├── requirements.txt
├── .streamlit/config.toml
└── 各厂区所有巡查项---2026年1月1日至2026年7月31日/   # 示例数据
```

### 为什么用 SQLite 存数据库

- 标准库自带，不用装数据库服务，一个 `data/inspection.db` 文件跟着项目走
- 支持 SQL 查询，几万条数据检索仍是毫秒级
- 关掉页面再打开会**自动载入上次整理的数据**，不必重新上传

表结构：

```sql
inspections(序号 INTEGER PRIMARY KEY, 日期 TEXT, 厂区 TEXT, 巡查发现 TEXT,
            来源文件 TEXT, 台账类型 TEXT)
```

> 旧版本建的库没有「厂区」列。程序会自动识别并重建这张表（它只是上次汇总结果的
> 缓存），你只需重新上传汇总一次即可。

## 性能说明：为什么「上传」会觉得慢

整个过程分两段，慢的往往不是同一段：

| 阶段 | 决定因素 | 能否优化 |
|---|---|---|
| ① 浏览器 → 服务器传输 | **你的上传带宽 + 网络延迟**（9.6 MB） | 打包成 ZIP 可把 17 次请求降为 1 次 |
| ② 服务器解析 Excel | 服务器 CPU | 已优化，见下 |

解析阶段做过的优化（同一批 17 个文件、同一台机器实测）：

| 版本 | 解析耗时 |
|---|---|
| 初版（openpyxl + 探测读一遍再全量读一遍） | 5.9 s |
| 改用 [calamine](https://pypi.org/project/python-calamine/)（Rust 实现）+ 每张表只读一次 | **1.5 s** |

- `python-calamine` 装不上时会**自动回退 openpyxl**，功能不受影响，只是慢一些
- 界面上「完成！…」提示里会显示本次实际解析耗时，方便判断是网络慢还是解析慢
- 免费层的服务器 CPU 比本地弱不少，同样的数据在云端会比上面的数字慢几倍属正常

### 界面交互速度

Streamlit 的机制是**每次交互都重跑整个脚本**，所以任何写在脚本里的重活都会被反复执行。
实测（68,499 条数据）定位到两个大头，都已按内容签名缓存：

| 每次 rerun 原本都在做的事 | 单次耗时 |
|---|---|
| `st.download_button(data=...)` 重新生成整份汇总 Excel | 1774 ms |
| kaleido 渲染图表 PNG | 1241 ms |

另外关键词匹配也做了优化：改用 numpy + Python 原生 `in`（比 `pandas.str.contains`
和 `pyarrow.match_substring` 都快约 3 倍），`&` 查询逐步收窄候选集、`|` 查询跳过已命中行，
并把预处理后的搜索数组和每个关键词的命中数缓存起来复用。

优化前后（本地实测）：

| 操作 | 优化前 | 优化后 |
|---|---|---|
| 筛选 | 2.0 – 2.3 s | **0.4 – 0.6 s** |
| 添加一个关键词 | 2.0 – 4.0 s | **0.3 – 0.5 s** |
| 切换一个勾选框 | 3.3 s | **0.4 s** |
| 生成图表 | 3.7 s | **1.0 s** |

> 高清 PNG 默认不预先生成（勾选后才做）。图表右上角的 📷 本来就能即时存图，
> 不需要服务器参与。

## 部署到公网

### Streamlit Community Cloud（免费）

1. 打开 <https://share.streamlit.io>，用 GitHub 登录
2. **New app**，填写：
   - Repository：本仓库
   - Branch：本分支
   - **Main file path：`inspection_app.py`**
3. Deploy

### Render（免费，休眠后冷启动约 30–60 秒）

- Build Command：`pip install -r requirements.txt`
- Start Command：
  ```
  streamlit run inspection_app.py --server.port=$PORT --server.address=0.0.0.0 --server.headless=true
  ```

> 云端注意：容器文件系统是临时的，`data/inspection.db` 会在应用重启后丢失，重新上传整理即可。若 kaleido 在云端不可用，PNG 按钮会自动禁用并提示改用 HTML 或图表自带的相机按钮。

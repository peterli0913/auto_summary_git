# 值班报告汇总

用户给出一批厂区发来的值班 / 驻厂 / 巡查邮件（.msg），以及要汇总的日期。按下面的脚本生成 Excel，不要手抄，也不要编造邮件里没有的行。

脚本和本说明放在同一目录：`summarize_duty_reports.py`。

## 先装依赖

```bash
pip install -r requirements.txt
```

需要 `extract-msg`、`beautifulsoup4`、`openpyxl`。不要改用别的库重写。

## 运行

只汇总一天（含当天，也含次日中午前收到的夜班）：

```bash
python summarize_duty_reports.py --input "邮件所在文件夹" --start 2026-07-09 --end 2026-07-09 --output "汇总_2026-07-09.xlsx"
```

汇总连续多天时，`--start` 和 `--end` 都写上，日期写 `2026-07-09` 这种格式。

不想把次日上午的夜班邮件算进前一天时，加上 `--no-overnight`。

终端会打印每封邮件是「纳入」还是「跳过」，以及原因。把这份清单连同 xlsx 一起交给用户。

## 怎样选邮件，避免漏掉

一封 .msg 只要满足下面任意一条，就纳入：

- 文件名里的日期落在范围内
- 主题里的日期落在范围内
- 正文开头的值班日期、驻厂日期落在范围内
- 表格「日期」列落在范围内

文件名没有日期的邮件也要看，例如「DH1-4 5号楼生产值班报告.msg」靠正文里的值班日期识别。

夜班报告经常拖到第二天上午才发出。结束日的次日 12:00（北京时间）之前收到、且内容是值班 / 驻厂 / 巡查的邮件，默认算进这一天，避免漏掉。正文日期已经明确是更后面那天的，不往前一天塞。

主题以「答复」「回复」「Re」「Fw」「转发」开头的，如果原信已经纳入，就跳过。答复里通常是把原表又贴了一遍，再计一次会重复。只有文件夹里没有原信、只剩答复时，才解析这封答复。

事件描述里出现的设备有效期、过期日，不拿来判断这封邮件属于哪一天。

## 输出长什么样

一个工作表，12 列，顺序固定，不要增删列：

来源、发件人、巡查类型、日期、厂区、属地、责任区域、第一责任人、责任人、隐患分级、事件描述、隐患类型

版式与示例一致：微软雅黑，表头 9 磅加粗，正文 8 磅，细边框，水平垂直居中，自动换行。列宽与示例相同。日期格式 `mm-dd-yy`。单日的工作表名是 `2026.7.9`，多日是 `2026.7.9-2026.7.10`。表头冻结。行高按描述长度加高，避免长文本被裁掉。

## 各列怎么填

- **来源**：从主题去掉「答复:」「【值班报告】」、日期和人名。`DH1-1、2、3号厂房07/09/2026值班报告` 写成 `DH1-1、2、3号厂房值班报告`。
- **发件人**：优先用正文里的「值班人员」「驻厂人员」或签名里的中文名。邮件显示名本身是中文时直接用。只有拼音、正文也没有中文名时，保留显示名，不要猜汉字。
- **巡查类型**：只写成 `高管驻场`、`生产值班`、`外围值班`。高管巡查、高管驻厂都归到高管驻场。
- **日期**：只汇总一天时，这一列都写这一天。汇总多天时，写邮件表格或值班日期里的那一天。
- **厂区**：写成 `DH1`、`DH3`、`TJ3`、`TJ4` 这种代码。敦化 1 公司记为 `DH1`。
- **属地、责任区域、第一责任人、责任人、事件描述**：按邮件表格原文整理，去掉 Word 拆开文字时多出来的空格。整格都是「无异常」「N/A」「只报了在岗人数」的不收录。一条格子里有多条编号问题的，拆成多行。
- **隐患分级**：邮件里写了「一般隐患」或「重大隐患」就原样抄。写的是 N/A 或空着，这一列留空，不要改成重大隐患。
- **隐患类型**：最后一列，用关键词粗分，例如静电、跑冒滴漏、标识标牌、现场5S、行为/操作、高风险操作核查、设备异常、设备设施隐患识别、其他。这一列允许不准，不要为了分类去改前面的描述。

清单体（建筑物 / 巡查发现项 / 责任人那种，如 TJ4）里的楼层负责人名单不写入「责任人」列，与示例汇总表一致。

## 不要做的事

- 不要把同一封报告的原信和答复各算一遍。
- 不要因为示例里有某个厂区，就在这次邮件里编造该厂区的行。文件夹里没有的邮件，表里就不会有。
- 不要漏掉文件名没写日期、但正文或发送时间对得上的值班邮件。
- 不要改脚本去输出 12 列以外的诊断列。
